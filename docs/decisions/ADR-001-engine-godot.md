# ADR-001: Движок — Godot 4

## Статус
Принято.

## Контекст
Игра 2D, idle/incremental, один основной экран (или два связанных). Нужен движок, который легко даёт визуальную прогрессию, много мелких юнитов на экране, частицы, простой UI-магазин, и хороший экспорт и в браузер, и на десктоп.

Рассматривались: Godot 4 (GDScript), Unity, GameMaker, чистый Web (TS + PixiJS/Canvas).

## Решение
**Godot 4 (GDScript).**

Причины:
- Лучший 2D-движок под инкременталки такого типа: физика, много юнитов, частицы, тряска камеры — из коробки.
- Нодовая архитектура ложится на модульность (Бездна, спавнер Грухров, экономика, апгрейды, сохранения — отдельные ноды/сцены).
- Лёгкий, бесплатный, открытый.
- Экспорт в HTML5 (тест) и десктоп/Steam (релиз) без боли.

Отклонено:
- Unity — избыточен для 2D-инкременталки, тяжёлый рантайм.
- GameMaker — проприетарный, платный.
- Чистый Web — жизнеспособен, но физику и сцены пришлось бы собирать руками.

## Оговорка про процесс прототипирования
Быстрые прототипы ядра механики (проверить, интересно ли вообще то, что мы придумали) делаются в HTML/JS прямо в чате с Claude — потому что там результат виден и играбелен сразу, без экспорта. Три таких прототипа уже сделаны (см. `docs/06_Development/Repo_Current_State.md`) и живут вне этого репозитория как черновики ощущений от механики, не как часть кодовой базы.

Реальная реализация игры — на Godot 4, через Claude Code, с git и headless-проверками.

## Последствия
- Основной код — GDScript в `/game`.
- Ассеты — простые фигуры/минимализм на старте (Правило дизайна из `AGENTS.md`).
- Сохранения — JSON, не бинарные ресурсы.
- HTML/JS-прототипы не переносятся как код — они справочный материал для того, «как это ощущается», не основа для порта.
